# 🚗 Telegram-бот мониторинга очереди на границе

Бот показывает ситуацию на белорусских пунктах пропуска (Брест, Берестовица, Брузги) по данным официального сайта [mon.declarant.by](https://mon.declarant.by/): сколько машин в живой очереди, как долго ждать и когда вызовут вашу машину. Расчёт времени ожидания опирается на историю, которую бот копит сам.

---

## 📋 Возможности

### 🌍 Зоны ожидания
- **Брест** (Брест-ТС)
- **Берестовица**
- **Брузги**

Зону можно сменить в любой момент (кнопка «🌍 Зона»), мониторинг при этом продолжается автоматически.

### ⏱️ Интервал опроса
- Быстрые пресеты: 3 и 10 минут.
- Свой интервал: от 1 до 1440 минут.
- Отчёт приходит в чат каждый раз по истечении интервала, кнопка под отчётом ведёт на сайт мониторинга выбранной зоны.

### 🎯 Фильтр по номеру машины
- Отслеживание конкретной машины: позиция в очереди и статус.
- После установки фильтра бот напоминает включить сирену.
- Фильтр снимается одной кнопкой.

### 🚨 Сирена при вызове в ПП
- Включается кнопкой «🔔 Включить сирену» (выключается «🔕 Выключить сирену»).
- Когда машина из фильтра получает статус «Вызван в ПП», бот присылает предупреждение и **переходит на ускоренный опрос каждые 30 секунд**.
- Как только статус машины меняется, ускорение отключается, и бот возвращается к обычному интервалу.

### 📊 «Оценка для вас»
- **Сбор истории:** фоновый сборщик каждые 30 минут сохраняет статистику по всем зонам, независимо от активности пользователей.
- **Усреднение:** расчёт строится на средних значениях за выбранный период, что сглаживает всплески.
- **Прозрачность:** в отчёте указано, на основе скольких записей и за какой период сделан расчёт.
- Время показывается в удобном формате: «~X ч Y мин.», а для больших значений «~X сут. Y ч Z мин.».

### ⚙️ Админ-панель (только для владельца)
- **📊 Период усреднения:** 6, 12, 24 (по умолчанию), 48 или 72 часа.
- **👥 Пользователи:** просмотр списка, блокировка, разблокировка, удаление.
- **💾 Бэкап базы:** файл `bot_users.db` приходит в Telegram.
- **📈 График очереди:** за 24, 48, 72 часа или 10 дней (нужен `matplotlib`).
- **🇵🇱 Время ожидания (Польша):** данные выезда из РП по пунктам Тересполь, Бобровники, Кузница и др. с сайта [granica.gov.pl](https://granica.gov.pl/) (обновляются на сайте 8 раз в сутки).

### 🔐 Автоматическая подпись запросов к API сайта
Запросы к сайту подписываются так же, как это делает его собственный JS (токен по времени и proof-of-work заголовок `X-Api-Word`). Сайт время от времени меняет секрет, поэтому бот **сам следит за изменениями**:
- при пустой очереди и идущем потоке машин он скачивает JS сайта и вытаскивает оттуда секрет, сложность и ключ;
- если значения изменились, подставляет новые и сразу повторяет запрос;
- проверки идут не чаще раза в 15–60 минут.

### 🔔 Уведомления администратору
Бот сам пишет владельцу (`ADMIN_CHAT_ID`), когда что-то происходит:

| Событие | Сообщение | Как часто |
|---|---|---|
| Сайт сменил параметры подписи, бот подхватил | 🔄 с новым секретом и числом нулей | каждый раз |
| Параметры не найдены в JS сайта | ⚠️ нужна ручная правка | раз в 6 ч |
| Не удалось скачать JS сайта | ⚠️ с текстом ошибки | раз в 6 ч |
| Очередь пустая 6 опросов подряд при идущем потоке | ⚠️ возможна смена алгоритма (или очередь действительно пуста, например ночью) | раз в 12 ч |

### 🛡️ Надёжность
- Если API 3 раза подряд вернул ошибку, мониторинг для пользователя безопасно останавливается с уведомлением («запустите заново: /start»).
- После перезапуска сервиса мониторинг пользователей **автоматически возобновляется** по сохранённым настройкам.
- Встроенный Flask-сервер отвечает на проверки `HEAD /` (нужно для хостингов вроде Render).
- Записи статистики старше 10 суток удаляются автоматически.

### 📈 Активность пользователей
Для каждого пользователя хранятся время последнего действия и счётчик сообщений. Статусы: 🟢 активен, 🟡 недавно, 🔴 давно.

## ⚙️ Локальная установка и запуск

1. **Клонирование:**
   ```bash
   git clone https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
   cd ВАШ_РЕПОЗИТОРИЙ
   ```

2. **Виртуальное окружение:**
   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # Linux / macOS:
   source .venv/bin/activate
   ```

3. **Зависимости:**
   ```bash
   pip install -r requirements.txt
   ```
   Обязательные: `pyTelegramBotAPI`, `Flask`, `requests`, `python-dotenv`.
   Желательные (бот работает и без них, но с ограничениями): `curl_cffi` (запросы под видом браузера), `matplotlib` (графики), `beautifulsoup4` (данные польской стороны).

4. **Переменные окружения** (файл `.env` в корне проекта):
   ```env
   API_TOKEN=токен_от_BotFather
   ADMIN_CHAT_ID=ваш_telegram_id
   ```
   Свой ID можно узнать у бота [@userinfobot](https://t.me/userinfobot).

5. **Запуск:**
   ```bash
   python botALLPL.py
   ```

## 🔧 Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `API_TOKEN` | да | Токен бота от @BotFather (можно также указать `api_token` в `bot_config.json`) |
| `ADMIN_CHAT_ID` | да | Telegram ID владельца, получает админ-панель и уведомления |
| `API_SECRET` | нет | Секрет подписи запросов к API сайта. Обновляется автоматически из JS сайта, переменная нужна только как начальное значение |
| `API_KEY` | нет | Ключ `X-Api-Key` сайта, тоже обновляется автоматически |
| `API_POW_ZEROS` | нет | Сложность подписи (число нулей в начале хэша), по умолчанию `3`, обновляется автоматически |

## 🚀 Развёртывание (Render и другие хостинги)

Бот работает на любом хостинге с Python 3 (Render, Railway, VPS, Docker и др.).

**Render:**
- Тип сервиса: Web Service. Команда запуска: `python botALLPL.py`.
- В разделе Environment задайте `API_TOKEN` и `ADMIN_CHAT_ID`.
- Бот слушает порт `10000`.
- Деплой запускается автоматически при `git push`.

> ⚠️ **Важно про базу данных.** Без подключённого Persistent Disk файловая система Render при каждом деплое возвращается к состоянию из репозитория, и всё, что бот записал за это время (история, пользователи), теряется. Если диска нет, перед обновлением делайте бэкап базы (см. ниже).

> ⚠️ При каждом деплое Render ненадолго запускает вторую копию бота. В логах при этом может появиться `409 Conflict: terminated by other getUpdates request`. Это нормально. Если ошибка не исчезает, значит, бот запущен ещё где-то с тем же токеном.

## 💾 Безопасное обновление бота и базы данных

`bot_users.db` хранит историю статистики (для точных расчётов) и список пользователей.

1. **Сохраните актуальную базу:** в боте откройте админ-панель, нажмите **«💾 Бэкап базы»** и скачайте файл из Telegram.
2. Положите скачанный `bot_users.db` в папку проекта поверх старого.
3. Убедитесь, что файл не в `.gitignore` (иначе используйте `git add -f`).
4. Проверьте код и отправьте на GitHub:
   ```bash
   python -m py_compile botALLPL.py
   git add botALLPL.py
   git add -f bot_users.db
   git commit -m "Обновление бота"
   git push
   ```
5. Дождитесь, пока деплой на хостинге перейдёт в статус Live.

> 🔒 Репозиторий с базой должен быть **приватным**: в ней лежат Telegram ID и имена пользователей.

## 🗄️ Структура базы данных

### `users`
| Поле | Описание |
|---|---|
| `chat_id` | Telegram ID пользователя |
| `username`, `first_name`, `last_name` | Данные профиля |
| `joined_at` | Дата регистрации |
| `is_blocked` | Блокировка (0 / 1) |
| `last_activity` | Время последнего действия |
| `message_count` | Счётчик сообщений |

### `border_stats`
| Поле | Описание |
|---|---|
| `id` | ID записи |
| `timestamp` | Время снятия показаний |
| `zone_key` | Зона: `brest`, `berestovitsa`, `bruzgi` |
| *прочие поля* | Количество машин в очереди, поток за час и за сутки |

Записи старше 10 суток удаляются автоматически.

### `monitor_prefs`
Настройки мониторинга пользователя: зона, интервал, чтобы после перезапуска сервиса мониторинг продолжился сам.

## 🛠️ Решение частых проблем

| Проблема | Решение |
|---|---|
| **Очередь пустая, хотя на сайте машины есть** | Сайт, скорее всего, сменил секрет подписи. Бот обычно подхватывает его сам (смотрите сообщения администратору и строки `[PARAMS]` в логах). Если не справился, скачайте новый `main.*.js` сайта и найдите в нём `intercept` / `createApiWord`, либо задайте `API_SECRET` и `API_POW_ZEROS` вручную. |
| **Ошибка 409 в логах** | Запущено несколько копий бота с одним токеном. Остановите лишние. На Render краткое появление при деплое нормально. |
| **`SyntaxError` при деплое** | Файл `botALLPL.py` склеился из двух копий (новый код вставили в конец старого). Замените файл целиком и проверьте `python -m py_compile botALLPL.py`. |
| **Сирена не срабатывает** | После установки фильтра нужно нажать «🔔 Включить сирену». Сирена реагирует только на статус «Вызван в ПП». |
| **Мониторинг остановился** | После 3 ошибок API подряд бот останавливает поток и просит прислать `/start` заново. |
| **База не сохраняется / обнулилась** | Проверьте `.gitignore` (`git add -f bot_users.db`) и наличие Persistent Disk на хостинге. |
| **Неточные расчёты** | Увеличьте период усреднения в админ-панели и подождите 24–48 часов, пока накопится история. |

## 🔒 Безопасность

- Токен бота храните только в переменных окружения или `.env`, не в репозитории.
- Админ-панель и служебные уведомления привязаны к `ADMIN_CHAT_ID`, запросы от других пользователей игнорируются.
- В базе хранятся Telegram ID, имена и настройки пользователей, поэтому репозиторий должен быть приватным.
- Бот использует только публичные данные сайта мониторинга и не обходит авторизацию.
